# `cards.csv` 数据字典

[`data/cards.csv`](../data/cards.csv) 是当前卡牌定义的唯一正式数据文件；[`assets/cards/`](../assets/cards/) 保存与之对应的卡图。文件现有 **722 行、46 列**：720 张可玩卡正面、1 张回合顺序参考卡、1 张公共牌背。每一行表示一种牌面定义，不表示对局中的一张卡牌实例；以后实现牌库、玩家手牌等，应让实例引用 `card_id`。

CSV 使用带 BOM 的 UTF-8 编码。读取时所有单元格先按字符串处理；下表的“整数文本”表示非空值可转换为整数。**空字符串表示未记录、未知或不适用，不等于数值 `0`**。部分数值可以为负数，部分文字单元格（尤其 `effect_text`）含有被 CSV 引号包裹的换行。

## 字段：编号与来源位置

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| `card_id` | 唯一文本 | 正式稳定编号。可玩正面为 `TS-0001`～`TS-0720`；另有 `TS-REFERENCE-001` 和 `TS-BACK-001`。图片以此命名。 |
| `source_card_id` | 唯一文本 | 原始图集格子标识，例如 `deck_18_10x7_r06_c04`；保留旧文件名的主体，供追溯，不是游戏中的主键。 |
| `catalog_order` | 整数文本 | 当前目录顺序，现为连续的 `1`～`722`。展示时按此字段升序排列；它不是卡牌在牌库中的顺序。 |
| `slot_kind` | 枚举 | `front` 可玩正面、`reference` 回合顺序参考卡、`back` 公共牌背。只有 `front` 进入可玩卡定义集合。 |
| `tts_card_id` | 整数文本或空 | TTS 存档中的 `CardID`，用于和原模组对照；公共牌背为空。不要将它当作正式编号。 |
| `tts_copy_count` | 整数文本 | 当时 TTS 存档中该牌位的实例数，仅是存档快照，不等于规则规定的供应数量。 |
| `deck_id` | 两位数字文本 | 原图集编号，当前覆盖 `01`～`20`；保留前导零。 |
| `row` | 整数文本 | 该牌位在原图集中的行号，从 `1` 开始。 |
| `column` | 整数文本 | 该牌位在原图集中的列号，从 `1` 开始。 |

## 字段：分类、文字与图片

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| `card_type` | 枚举或空 | 一级分类，完整枚举见下文；唯一公共牌背为空。 |
| `subcategory` | 枚举／英雄系列名／空 | 二级分类。基础牌、村庄牌、疾病牌和参考卡为空；英雄牌填写所属系列。具体组合见下文。 |
| `hero_series_status` | 枚举或空 | 英雄系列匹配结果。英雄牌当前使用 `matched`、`four_cards`、`special_series`；其他牌为空。 |
| `hero_series_size` | 整数文本或空 | 同系列中**不同卡名**的数量，不是印刷张数；当前英雄系列为 `2`、`3` 或 `4`，其他牌为空。 |
| `name` | 文本或空 | 中文卡牌名称，通常来自卡面顶部；公共牌背为空。 |
| `waist_text` | 文本或空 | 卡面腰部的原样中文标签，例如 `战士・盗贼`；参考卡、牌背为空。 |
| `tags` | `\|` 分隔的文本或空 | 从 `waist_text` 按 `・` 拆分、去首尾空格、按出现顺序去重，例如 `战士\|盗贼`。标签不等于 `card_type`；村庄牌、基础牌也可能带“英雄”标签。 |
| `effect_text` | 可含换行的文本或空 | 卡面规则正文。现有整理结果通常每条独立效果占一行，卡面排版产生的句中折行已合并；没有规则正文时为空。 |
| `other_text` | 可含换行的文本或空 | 未归入名称、腰部或效果的其他卡面文字；当前主要是雷霆之石的风味文字。 |
| `review_status` | 枚举 | 早期中文文字整理状态：`extracted`、`reviewed`、`not_applicable`。这是历史记录，不表示当前存在审核页面。 |
| `review_reasons` | 文本或空 | 早期文字待核对原因码，多个值原拟用 `\|` 分隔；当前全部为空。 |
| `legacy_edited` | 布尔样式文本 | 早期嵌字工程的编辑标记，当前全部为字面值 `True`；不应用它推断最终人工核对状态。 |
| `image_path` | 项目根目录相对路径 | 正式中文卡图，例如 `assets/cards/TS-0679.png`；公共牌背为 `assets/cards/TS-BACK-001.jpg`。该路径对应的文件是正式资产。 |
| `english_image_path` | 相对路径 | 英文原卡图路径，位于本地 `black_edges/`；该初期资产目录被 Git 忽略，部署时不保证存在。 |
| `clean_image_path` | 相对路径 | 英文文字抹除后的中间图路径，位于本地 `black_edges/.card_localizer_work/`；同样不属于正式卡图。 |

## 字段：Wiki 对照与卡面数值

`wiki_` 前缀表示这些值最初经卡表对照导入，后来可能经过人工修订；它们是 CSV 中的最终快照，不要求运行时访问 Wiki。`正文_` 前缀的两个值由中文效果正文提取，不是 Wiki 的独立列。下列数值字段非空时均为整数文本；印刷的动态 `*` 符号另存于 `wiki_印刷符号`。

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| `wiki_英文卡名` | 文本或空 | 对应的英文卡名，用于与原卡和卡表核对。 |
| `wiki_卡表扩展` | 枚举或空 | 对应卡表或扩展来源；当前七个非空取值见下文。 |
| `wiki_购买价格` | 整数文本或空 | 卡面／卡表所列购买或雇佣价格，与卡牌提供的金币值分开。 |
| `wiki_金币值` | 整数文本或空 | 卡牌的金币值；不等于购买价格。 |
| `wiki_光照` | 整数文本或空 | 卡面列出的光照值，可以为负数；效果正文里的临时光照修正仍在 `effect_text` 中。 |
| `wiki_重量` | 整数文本或空 | 卡面列出的重量值。 |
| `wiki_英雄等级` | 整数文本或空 | 卡面／卡表中的英雄等级，当前可见 `0`～`4`；也可能出现在带“英雄”标签的基础牌或村庄牌上。 |
| `wiki_力量` | 整数文本或空 | 卡面列出的力量值，主要用于英雄及带英雄标签的牌。 |
| `wiki_生命值` | 整数文本或空 | 怪物、守护者等的生命值；部分怪潮／虫群牌的数值最初按牌阵顺序推定，相关依据保留在备注和匹配状态中。 |
| `wiki_经验值` | 整数文本或空 | 卡面经验值原值。英雄及带“英雄”标签的基础牌／村庄牌代表升级所需经验；怪物和守护者代表击败奖励。对应的语义字段见下表。 |
| `wiki_胜利点` | 整数文本或空 | 卡面列出的固定胜利点，可为负数；若印刷为动态 `*`，符号另存，不把它猜成固定整数。 |
| `正文_基础攻击` | 整数文本或空 | 从中文效果正文中识别出的基础攻击值；不代表所有条件、装备或临时修正后的最终攻击。 |
| `正文_基础魔法攻击` | 整数文本或空 | 从中文效果正文中识别出的基础魔法攻击值，同样不是最终战斗合计。 |
| `wiki_印刷符号` | 文本或空 | 用“字段名:`*`”记录卡面印刷的动态值，当前如 `wiki_胜利点:*`；不是数值 `0`。 |
| `wiki_匹配状态` | 枚举 | 早期卡表对应方式／适用性说明，具体七种取值见下文；与人工数值审核状态不同。 |
| `wiki_数据备注` | 文本或空 | 卡表来源、数值推定或特殊替换牌的说明；这是来源备注，不自动转成游戏规则。 |
| `wiki_来源链接` | HTTPS URL 或空 | 对应卡表页面的来源地址，供追溯。 |

## 字段：语义经验值与人工备注

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| `upgrade_xp_cost` | 整数文本或空 | 升级该英雄所需的经验值。用于英雄牌，以及带“英雄”标签的基础牌、村庄牌；来源为 `wiki_经验值`。 |
| `defeat_xp_reward` | 整数文本或空 | 击败该怪物或守护者时获得的经验值；来源同为 `wiki_经验值`。 |
| `wiki_review_status` | 枚举 | 早期数值人工审核状态，当前为 `reviewed` 或 `not_applicable`；独立于 `wiki_匹配状态` 和文字的 `review_status`。 |
| `wiki_review_note` | 文本或空 | 数值审核的人工备注；当前全部为空。 |
| `review_note` | 文本或空 | 中文文字／分类审核的人工备注；当前两行有值。 |

非空的 `wiki_经验值` 必须恰好进入 `upgrade_xp_cost`、`defeat_xp_reward` 其中之一，另一列留空；原值即使为 `0` 也要保留。当前 330 个非空经验值分别对应 108 个升级费用和 222 个击败奖励。

## 数据关系与使用约束

- `card_id`、`source_card_id`、`catalog_order` 当前各自唯一。按 `catalog_order` 显示，按 `card_id` 引用卡牌定义；修改正式编号时还需同步改图片文件名和 `image_path`。
- `image_path` 指向受项目管理的正式图片；`english_image_path`、`clean_image_path` 仅供本地追溯，不能作为网页发布时必有的图片。
- 若修改 `waist_text`，应同步检查 `tags`；若修改英雄系列或卡名，应检查 `hero_series_size`、`hero_series_status`；若修改 `wiki_经验值` 或相关分类，应同步检查两个语义经验值字段。
- 审核相关字段保留历史状态。当前没有审核页面或数据重建程序；最终卡牌资料以本 CSV 为准，不从早期图集或 Wiki 再次自动生成。
