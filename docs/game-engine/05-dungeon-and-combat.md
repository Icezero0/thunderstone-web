# 地下城、战斗与终局

本文件展开《飞龙尖塔》规则书第 9～20、24 页的标准地下城流程。它描述基础时点和状态变化；单张卡牌覆盖通则时，由 [能力运行时](06-ability-runtime.md) 提供有来源的修改。

## 1. 一次地下城行动的结算顺序

| 顺序 | 子阶段 | 主要处理 |
| ---: | --- | --- |
| 1 | `DUNGEON_REVEAL` | 展示整手牌，结算强制展示/战利品效果 |
| 2 | `DUNGEON_PREPARE` → 按需 `BATTLE_COMMIT` | 使用地下城能力，选择参战英雄、支援及装备；“完成”只提交队伍，结算装备事件和恶疫／疲惫，准备阶段的摧毁立即生效 |
| 3 | `DUNGEON_DECLARE` | 独立等待玩家选择大厅中的阶层和怪物，通过 `DeclareBattleTarget` 宣言攻击；可返回调整队伍 |
| 4 | `BATTLE_RESOLVE` | 计算攻击、光照和限制；结算该目标战斗效果并重新计算，判定胜负 |
| 5 | `BATTLE_REWARD` | 胜利先结算凯旋，再执行摧毁标记；之后怪物离场，胜利取得怪物与经验，失败按规则退回 |
| 6 | `HALL_REFILL` | 大厅低阶层补位、翻开新牌；依序结算陷阱、宝藏等 |
| 7 | `BREACH_AND_END_CHECK` | 结算移动至阶层 1 的突破及即时终局条件 |
| 8 | `TURN_WILL_END` → `TURN_CLEANUP` | 处理剩余延迟效果、弃牌、抽下一手牌；已确认终局时改入 `SETTLING` |

规则书第 24 页把大厅补充后的陷阱放在突破之前。进入阶层 1 的雷霆之石使标准对局立即结束；它的判定不能被普通回合末抽牌拖后。某张卡牌若改变上述顺序，需要明确的替代或延迟规则。

## 2. 准备、装备与目标

进入地下城时必须展示手牌。可选地下城能力由玩家决定是否、按什么顺序使用；强制效果和手牌战利品必须结算。准备阶段被摧毁的牌立即离场，之后不能再贡献印刷数值、能力或作其他费用。新抽到的牌加入当前手牌和本次计算。

每名英雄通常最多装备一件武器，每件武器只能装备给一名英雄。武器重量 `<=` 英雄当前力量才合法；未装备武器没有收益。力量变化使已装备武器超重时，该武器脱落并立即失去收益。某些卡牌会允许额外装备或记录“本场战斗曾装备”，因此分别保存当前装备关系和历史事实。法术、物品和战利品可以在没有英雄时提供收益。

多武器英雄以全部武器的**有效重量总和**校验力量，每张托林护手各增加一个武器名额。魔法灵气使有效重量为零，查询武器重量的其他效果也读取零。武器地下城主动能力通常需要已装备，霜巨人战斧等明文允许未装备使用的牌例外。法术勾选／取消均为本地预览，不登记使用；实际发动其能力，或提交战斗队伍时仍选中，才记录使用。取消勾选不会撤销已经发动的能力或已提交的使用记录。

准备结束后，网页版通过 [`SubmitBattleTeam`](battle-team-api.md)提交参战英雄、使用的支援牌和装备，不提交目标。结清提交时的强制效果后，进入第三阶段 `DUNGEON_DECLARE`，再通过 `DeclareBattleTarget` 选择阶层和怪物。`ReviseBattleTeam` 可返回准备，已执行效果及使用记录不会撤销。所有牌无论是否选中参战都保留在原手牌区，已装备武器也一样；`battle_context.battle_team` 只按实例 ID 记录参战状态，装备关系另行记录。手牌范围的效果同时包含参战和未参战卡牌，仅明确限定参战对象时才按参战状态筛选。未参战英雄可以在准备阶段使用地下城能力，但其自身数值、持续战斗加成与战斗／凯旋能力不参与本场。法术可以独立于英雄参战，疾病与强制战利品不能关闭。

必须选一个目标，即使队伍预计无法取胜。规则书区分“不能攻击”和“不能击败”：禁止使用某牌收益后攻击的特性可能使目标不合法；“需要魔法攻击”则可能允许宣告但导致无法击败。目标是否合法由当前使用的牌和怪物限制判断，不能只比较生命值。

## 3. 攻击计算与解释账本

引擎需保存各来源的贡献和处理顺序，而非只有一个攻击总数。标准计算可描述为：

1. 分别收集普通攻击和魔法攻击的牌面值、装备收益、地下城效果与持续修正。对免疫、受限英雄、禁止使用的牌逐项筛掉或调整来源。
2. 结算疾病等负修正。疾病卡的 `-1` 在应用前选择当时至少有 `+1` 的一种合法攻击类型；普通与魔法攻击不能因一张疾病同时各减 1。某一来源或分项的值可以为负。
3. 应用规则要求的最终翻倍、减半及向下取整。规则书明确：总攻击翻倍在计入疾病等攻击修正后、**光照惩罚之前**处理。怪物的法术免疫、魔法攻击免疫、只能用魔法攻击等限制并不等价，必须分别表达。
4. 对普通阶层计算未被抵消的光照惩罚：`max(0, 阶层基础惩罚 + 有效怪物/环境修正 - 有效光照)`。每 1 点未抵消惩罚使攻击减少 2；过量光照不加攻击，光照惩罚不能使最终攻击低于 0。阶层 0 守护者战斗的光照惩罚恒为 0。不能减少光照惩罚等特性可替代这个标准式。
5. 在目标战斗效果改变力量、装备、攻击或生命值后重新求值，并应用目标的击败条件。最终有效攻击 `>=` 当前有效生命值且所有强制条件满足，才判为击败。

例如阶层 2 怪物在没有其他修正时基础光照惩罚为 2；若队伍有效光照为 1，剩余惩罚为 1，最终攻击减少 2。此类中间值应出现在可审计的 `CalculationTrace` 中：来源实例、原值、修正原因、处理时点、有效/被免疫状态、最后合计。客户端展示战斗说明可以读取这份账本，不自行重算。

## 4. 战斗效果与摧毁时点

被攻击怪物的战斗效果无论胜负都执行。准备阶段已经生效的地下城效果先于怪物战斗效果；战斗效果可能降低力量、给予疾病、阻止某英雄攻击或标记摧毁。战斗中获得的疾病进入弃牌堆，不影响当前战斗。

2026-10-24 裁定：有“战斗：”前缀的数值修正在每次结算时取值并保存，可被苦痛守卫重复或红宝石龙免疫；没有该前缀的持续修正仍随当前状态计算。两次半伤乘为四分之一，最终应用除数并向下取整。恶疫／疲惫的强制力量惩罚延后到 `BATTLE_TEAM_COMMITTED`，让玩家先在准备阶段使用增益；其后记录零力量并处理武器脱落。零力量摧毁按当前裁定在战斗结算处理。氏族系列的地下城加成是主动能力，不再自动作为光环生效。

没有明确要求立即执行的战斗摧毁先标记，牌仍参与本次战斗。实际执行的边界是**判定胜负及凯旋结算之后、怪物离场之前**；对应摧毁动画在同一事件位置播放，前端回放完成前保留第 4 阶段“结算战斗”。卡文明确写出“立即摧毁”或要求支付摧毁费用时，当场执行，离场牌不再贡献之后的战斗数值。若摧毁被替代为弃牌，仍视为成功支付费用。

“摧毁改为弃牌”保存在英雄实例的 `flags.turn_buffs`，持续至当前回合结束。守护者之刃在装备时给予对应英雄该状态；盛宴、神馔在发动时给予手中所有英雄。取得状态后，英雄离开手牌、武器脱落或来源被移除都不撤销状态；期间的立即摧毁、战后摧毁、回合末摧毁均由弃牌替代，替代不消耗状态。处理后移除待摧毁标记，回合结束再清除保护，避免影响之后的回合。它属于原英雄实例，升级后新实例不会继承。

力量下降若使武器不再可装备，则武器收益立即失效，即使对应英雄仍参与到战斗结束。英雄在战斗中力量曾降至 `0` 时，保留与普通战斗摧毁相同的 `pending_after_battle_destruction` 标记，后来恢复力量也不撤销；判定胜负后、怪物离场前统一处理并播放对应动画。保护可以将该次摧毁替代为弃牌；若某个响应防止了该次摧毁，同一英雄不会因仍为零力量而被反复标记。移除力量光环导致的新零力量目标也在此窗口处理完。`TS-0717-A02`、`TS-0718-A02` 只是系统规则的提示引用，不重复摧毁。其他明确要求回合末摧毁的效果仍使用各自的回合末标记。

维里斯系列的武器加成是持续效果，来源英雄只有选中参战时才生效。按各等级卡文给手牌中当前合法装备的全部武器生成增益状态，未装备的武器不获得加成；武器所属英雄未参战时，武器仍有该状态，但不贡献战斗数值。取消来源参战、卸下武器或来源离场会立即移除相应状态。数值与状态投影复用 `weaponAuraApplications`，不将加成永久写入印刷数值或 `card_modifiers`。

其他持续修正也生成带来源名称的状态：英雄／物品／法术光环、按手牌计数与阶层变化的加成、装备条件加成、对特定怪物的加成、没有魔法攻击时的加成、额外光照转魔法攻击，以及大厅中的力量、疾病攻击、生命值和光照影响。数值证据由实际计算分支通过 `StatusEvidence` 记录；同一来源的力量、攻击、光照等合并展示，正负修正分别归入增益和减益。装备容量、装备力量减免、攻击类型转换、重量归零、无视光照、魔法攻击翻倍和村庄价格影响使用文字状态。作用于整支队伍或大厅的规则在来源牌上注明作用范围，怪物生命值加成则记录到实际受影响的怪物上。印刷基础数值无需重复作为增益显示，尚未发动的主动能力也不会预先变成增益。

这些状态是只读投影，随当前手牌、装备、参战选择、目标、来源离场和持续期限重新计算。前端使用同一引擎计算手牌及公开大厅的本地状态，替换旧的 `continuous: true` 条目；显式获得的临时增减益、保护和摧毁标记单独保留。状态仅更新卡牌标记及 空格 检视，不移动牌区，不产生网络命令，也不把预览写回权威对局。

要分别记录 `PENDING_AFTER_BATTLE` 和 `PENDING_AT_TURN_END`，并为每个实例去重。特殊卡牌可能明确改变延迟时点；运行时必须按具体能力的触发阶段执行。

## 5. 胜负、怪物去向与凯旋

胜利后先触发独立的 `BATTLE_TRIUMPH` 时点，结算英雄及目标怪物的凯旋；没有参战或不能参与攻击的英雄不贡献自身凯旋能力。带有摧毁标记但仍在手牌中的英雄此时仍可触发。凯旋全部完成后执行摧毁标记，再将被击败的怪物移入当前玩家弃牌堆并给予 `defeat_xp_reward`。其他“击败怪物后”效果仍在 `MONSTER_DEFEATED` 时点处理，不提前到凯旋。

2026-10-25 网页版裁定：凯旋开始时，自动根据所有剩余手牌生产一次金币，包括已装备的武器、未参战牌以及尚未真正摧毁的牌；已经离开手牌的牌不计入。多个凯旋购买机会**共用本次金币余额，购买后扣减，不重复生产金币**。DSL 使用 `buy.payment: "gold"`，按实时结算价格和供应顶牌筛选合法购买；跳过不扣金币，无合法牌时继续后续结算。购买选择会暂停工作流，完成后才继续摧毁及大厅补位。

失败时，普通怪物回到地下城牌堆底部。具有“必须被击败才离开”特性的怪物以及守护者不会因为失败离场；仍要结算适用的战斗效果。怪物离场后才开始大厅补位。记录胜负、经验发放、卡牌归属与去向为不同事件，方便环境牌替换其中一步。

## 6. 地下城大厅补位

大厅的标准可见阶层是 1、2、3。某张怪物离开后，较高阶层的牌依次向较低阶层移动，再从地下城牌堆顶补充阶层 3。需要记录每次 `HALL_ENTER` 和 `ENTER_RANK_1` 的实际原因；设置时就位于阶层 1 的怪物没有突破事件。

补牌翻出陷阱：将陷阱留在实际大厅阶层并暂停补牌，高亮等待当前玩家点击；`ResolveTrap` 开始执行效果，内部响应全部完成后移除并继续补足大厅。陷阱不再移到中央展示，移除动画在原位淡出；它实际仍进入已移除区，以支持后续洗回陷阱的效果。若环境规定陷阱到阶层 1 才触发，仍遵循该时机。补牌翻出宝藏：当前玩家立即获得并置于控制区，以后可按卡面摧毁发动效果；它不进弃牌堆。连续翻出这些卡时逐张处理，直到大厅只留下合法怪物或雷霆之石。循环需要“目标数量已完成”或“无牌可继续翻”之类的明确终止条件，不能以某轮没有命中目标就过早结束；这是 `TS-0689`、`TS-0693` 测试场景已确认的边界。

进入阶层 1 的怪物触发一次突破，随后不因为持续停留而反复触发。守护者到达阶层 1 时移至阶层 0 并补满大厅；阶层 0 可以有多名守护者。其持续效果影响所有玩家，阶层 0 攻击无光照惩罚。有守护者在阶层 0 时不能取得雷霆之石，但不阻止雷霆之石到达阶层 1 后结束游戏。

守护者具有“怪物”标签，通用怪物效果可以选择它。已确认的网页版约定：除卡文限制外，阶层 0 守护者可以返回所属地下城牌堆，包括与牌堆顶若干张一起洗混；阶层 0 不参与普通阶层的交换、换位或移到阶层 3，移走它也不补充普通大厅。死亡哨卫、黑暗勇士的“除非被击败，否则无法移除”继续限制移动，直接击败效果则可生效。返回牌堆不算击败；直接击败正常给予经验，末日之心的击败终局也适用。

## 7. 终局与计分

标准对局在雷霆之石到达阶层 1 时立即触发终局，当前 `Match` 从 `PLAYING` 进入 `SETTLING`。只有当前玩家**击败阶层 1 怪物**而直接使雷霆之石移入该阶层，且没有阶层 0 守护者阻止取得时，才取得这张雷霆之石；其他进入原因没有取得者。`TS-0199`“放逐仪式”等设置会改变雷霆之石与末日之心的终局条件，应作为独立规则覆盖。

已实现的场景覆盖：飞龙尖塔取得第一张雷霆之石后继续，取得第二张后结束；雷霆之石未被取得而进入阶层 1 时也结束。放逐仪式中取得雷霆之石不结束对局，无人取得的雷霆之石突破时放回地下城牌堆底部；击败末日之心或末日之心突破才结束。末日之心战斗使每张手牌雷霆之石获得**魔法攻击 +6**；其战斗败北效果仅淘汰攻击者，其余玩家继续，全员淘汰则无赢家。末日之心突破后不会移入阶层 0。上述时点和淘汰行为有 `test_scenario_engine.py` 的公开命令测试。

引擎在 `SETTLING` 阶段基于**同一个终局快照**为每位玩家合计其抽牌堆、手牌、弃牌堆和其他受其控制卡牌的胜利点，再加上剩余经验值，按 **1 XP = 1 胜利点**换算。返回的 `victory_points` 为总分，`card_victory_points` 为卡牌小计，`experience_points` 为经验换分；计分不消耗 XP。固定印刷值从卡牌目录取；印刷 `*` 的牌通过已编译的计分能力求值，不用空值或 0 代替。最高分获胜；同分时持有雷霆之石的玩家优先，否则同分者共享胜利。已淘汰玩家仍列出分数，但不参与胜者裁决。确认终局后不再执行普通回合末抽牌。引擎返回结果；联机层保存并发布结果后更新房间状态，详见[交接契约](00-engine-boundary.md)。

## 8. 必要测试片段

- 阶层 2、光照 1、无其他修正时，攻击因黑暗减少 2；阶层 0 守护者没有该惩罚。
- 准备阶段摧毁应急干粮后，该卡不能再提供力量；战斗效果摧毁的卡仍完成本次战斗。
- 英雄力量跌至 0 后恢复，仍在判定胜负后、怪物离场前只处理一次摧毁；武器因力量不足脱落时其加成立即消失。
- 普通怪物失败退回底部；守护者失败留在原阶层；两者的战斗效果都能发生。
- 连续陷阱和宝藏补厅时按出现顺序结算，宝藏进入控制区，突破只在合法移动进入阶层 1 时发生。
- 雷霆之石因胜利补位与因其他原因补位分别验证取得权，并测试阶层 0 守护者阻止取得但不阻止终局。
