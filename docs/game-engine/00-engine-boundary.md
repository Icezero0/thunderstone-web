# 联机层与游戏引擎的交接

玩家所在的房间与一局实际游戏是不同对象。**联机层**确定玩家列表以及玩家最终认可的配置；**游戏引擎**接收冻结后的配置与有序玩家列表，校验规则并执行组局、回合和计分。房间不设置座位对象。本文件定义二者之间的契约。局内状态见[状态模型](02-state-model.md)，联机适配见[联机章节](07-multiplayer.md)。

## 1. 职责边界

| 工作 | 负责方 | 交接结果 |
| --- | --- | --- |
| 创建/关闭房间、身份与权限、加入/离开、确定玩家列表 | 联机层 | 有序且身份已验证的玩家列表 |
| 展示规则选项、保存配置草稿、玩家准备、修改后撤销准备 | 联机层 | 经全员确认的规则配置快照 |
| 检查配置是否符合游戏规则、卡牌组是否存在且可执行 | 游戏引擎 | 带字段和原因的校验结果 |
| 抽随机设置牌、处理设置能力、生成供应/牌堆/初始牌库 | 游戏引擎 | 可重放的初始 `GameState` 与事件 |
| 合法行动、卡牌能力、战斗、终局条件与胜利点 | 游戏引擎 | `Transition`、终局快照和 `MatchResult` |
| 指令排队、存储、断线恢复、向玩家推送裁剪后的视图、归档结果 | 联机层 | 房间与对局记录；下一局可以重新配置 |

联机层可在配置界面请求引擎**只读预检**，但配置草稿、准备标志和玩家列表仍归联机层。游戏引擎不持有 `RoomState`，也不决定哪些登录用户有资格修改房间。引擎使用不含会话信息的 `player_id`；联机层负责把登录用户映射到本局玩家 ID。断线不会自动删除局内玩家或改变顺序。

## 2. 两条状态线

```text
联机层：房间闲置 → 收集配置与玩家准备 → 冻结启动请求 → 运行中 → 发布结果 → 房间闲置
游戏引擎：                    校验配置 → SETTING_UP → PLAYING → SETTLING → COMPLETED
```

`IDLE`、房间的配置草稿及 `ready_by_user_id` 是联机层状态，不进入规则内核。引擎的 `SETTING_UP` 从已冻结的启动请求开始；组局需要玩家选择时保留设置进度和 `PendingChoice`。完成设置后进入 `PLAYING`；终局事件使该局进入 `SETTLING`，生成并返回结果后为 `COMPLETED`。引擎没有“回到房间闲置”的转换；联机层在结果成功保存后将房间转回闲置。

同一房间至多有一个未完成对局，由联机层保证。每次开局使用新的 `match_id`。已经完成的对局保留只读快照和结果，不能把房间下一局的玩家、规则或随机数写回旧局。

## 3. 启动请求

联机层在玩家列表和规则配置确定且全员准备后，冻结并提交一个 `StartGameRequest`。示意结构如下；具体传输格式由服务接口决定。

```yaml
match_id: 本次对局唯一 ID
player_ids: [p1, p2]
rules:
  mode: classic
  counts: {village_groups: 8, hero_groups: 4, monster_groups: 3}
  selection:
    village: {fixed_randomizer_ids: []}
    hero: {fixed_randomizer_ids: []}
    monster: {fixed_randomizer_ids: []}
    dungeon_features: {mode: classic_random}
    guardian: {random_count: 0, fixed_card_ids: []}
    environment: {random_count: 0, fixed_card_ids: []}
    trap: {random_count: 0, fixed_group_ids: []}
    treasure: {random_count: 0, fixed_group_ids: []}
    thunderstone: {fixed_card_ids: []}
  instance_multipliers: {village: 1, hero: 1, monster: 1}
  first_player: {method: random}
catalog_version: 已选卡牌目录版本
ruleset_version: 已选规则包版本
rng_seed: 由服务端确定并记录
rng_algorithm_version: 已选随机算法版本
```

本地配置面板可用临时玩家列表和随机种子验证 setup；房间编辑模式只保存规则配置，玩家列表由联机层维护。正式开局时联机层冻结完整 `StartGameRequest`，面板的配置预检只覆盖规则参数及现有卡牌目录。

初期仅实现 `mode=classic`，使用完整卡牌目录，不提供扩展筛选。村庄 8 种、英雄 4 种、怪物 3 组是**默认值**，不是不可更改的规则常量；怪物组数不包含环境和其他地下城特征。确定环境时固定组数不得超过调整后的目标组数；随机环境若降低目标并造成已选组超额，组局时随机丢弃超出的组。未指定的组默认由随机设置牌补齐。`selection.dungeon_features.mode=classic_random` 时按经典流程将地下城特征牌洗入设置池，四类手动选择必须为空；`manual` 时不抽特征设置牌，只按四类选择构建。守护者和环境的 `fixed_card_ids` 指实际卡牌；陷阱和宝藏的 `fixed_group_ids` 指完整牌组，分别有 3 组和 4 组，内部借用对应特征牌 ID 作稳定组 ID。`random_count` 表示从未固定的实际卡牌或牌组中无放回抽取的数量；环境只能为 0 或 1，且与固定环境互斥。雷霆之石的 `fixed_card_ids` 可指定部分，剩余名额随机补足；普通环境目标 1 张，飞龙尖塔目标 2 张，放逐仪式强制选入全部 7 张并加入末日之心。环境随机时，设置阶段在抽出具体环境后应用相同修正；输入预检检查各可能环境调整后的目标仍在目录可用范围内。村庄牌、所有等级的英雄牌、怪物牌分别使用 ×1～×5 的统一倍率，实际实例数为 `cards.csv.initial_copy_count × 对应倍率`；其他类型仍用 CSV 默认值。组局细节见[组局章节](03-setup.md)和[生成目录的规则](01-catalog-and-rulesets.md)。

首位玩家可选随机、指定玩家、上一局唯一赢家或房主。联机层将后面三种方式解析为 `{method: fixed, player_id: ..., source: specified | previous_winner | host}`：查询历史结果、判断房主是否参赛等由联机层完成；引擎只校验该 `player_id` 在本局名单里，并在设置事件中保留 `source`。默认 `{method: random}` 由引擎使用本局随机数状态选择。后续回合按提交的 `player_ids` 列表顺序循环，不需要额外的座位编号。

`StartGameRequest` 不包含登录令牌、连接状态、准备标志或客户端计算的牌堆顺序。配置、玩家列表、目录和规则版本在同一局中保持不变。`match_id` 的重复提交应返回已有启动结果，不能创建第二套牌；幂等提交由联机层/存储层实现，引擎保证相同输入及随机状态产生相同规则结果。

## 4. 校验、组局和失败处理

引擎对冻结请求先做确定性校验：玩家 ID 不重复、人数及组数在规则允许范围内、固定组未超额、特征互斥、随机候选足够、指定首位玩家属于本局、所有可能进入牌池的卡牌能力已编译。校验失败返回可定位的错误，由联机层展示给玩家并回到配置界面；引擎不创建可玩的 `GameState`。联机层也可以在全员准备前用同一校验器预检草稿，以减少开局失败。

校验通过后，引擎在 `SETTING_UP` 中先纳入固定组，再按配置从随机设置牌池抽取不足的组，处理特征和设置能力，建立村庄供应、地下城、初始牌组与首回合。随机用途、候选集合、抽取结果以及设置选择写入事件。若设置能力等待玩家选择，引擎返回 `PendingChoice` 和可恢复的组局状态，联机层负责把选择送回指定玩家。过程中出现不可恢复的组局错误时，引擎返回诊断，不发布部分完成的局；联机层解除准备并允许修订配置。失败尝试另留审计记录，重新启动须使用新尝试 ID。

## 5. 对局和结果交回

`PLAYING` 中，联机层验证请求来自当前登录用户，并把其映射为本局 `actor_player_id`；引擎根据 `GameState` 验证行动与阶段，产出下一状态、事件、合法下一步和待选择项。终局条件成立时，引擎固定终局快照，进入 `SETTLING`，计算固定/动态胜利点、雷霆之石取得权及同分裁决，最终返回 `MatchResult`。标准模式的即时终局不再运行普通回合清理；具体条件见[战斗与终局](05-dungeon-and-combat.md)。

`MatchResult` 至少包含 `match_id`、玩家列表快照、规则与目录版本、胜利条件、逐玩家分数明细、赢家/平局和终局状态版本。联机层原子保存结果及事件，发布可见结果，解除该房间的活动对局关联，并使房间回到闲置。重复提交终局处理返回同一结果。下一局是否沿用配置或成员是联机层的房间产品行为，游戏引擎只接受新局的冻结请求。
